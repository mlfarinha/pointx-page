# PointX project page

The project page of *PointX: Multi-View Consistent Intrinsics by Querying Surface Points*.
A static site: no build step, no framework, no external requests (fonts and three.js are vendored) but the visitor counter's.

Live at https://pointx-paper.github.io/. The paper is arXiv:2611.33157 (https://arxiv.org/abs/2611.33157): the arXiv button and the
BibTeX entry carry it, the Paper button opens `assets/PointX.pdf`. The Code button is still marked "soon". The page is open to search
engines: no `robots` tag, and `<link rel="canonical">` names https://pointx-paper.github.io/ as the address to list (the same files
are also served at https://mlfarinha.github.io/pointx-page/). See "Going public" below.

## Look at it

    python3 serve.py                   # in this folder, then open http://localhost:8377 (sends Cache-Control: no-cache, so an edit shows on reload)

`python3 build_supplementary.py` writes the ANONYMOUS copy for a submission's supplementary material (no authors, links, buttons or
BibTeX; one folder whose `index.html` opens by double-click, and its zip): see the script's header for how a page runs from the disk.

After changing anything in `css/` or `js/`, raise the version in `index.html` (`sed -i -E 's/\?v=[0-9]+/?v=N/g' index.html`): the stylesheet and
every script carry `?v=N`, the import map passes it to the modules imported by other modules, so a browser that kept old copies
cannot run them against new data (seen: Safari / Chrome reloading the page yet running a cached module).

It must be served over HTTP (ES modules and `fetch` do not work from `file://`). On a remote machine, forward the port:
`ssh -L 8377:localhost:8377 <host>`.

### The scene format

`scene.json` holds the cameras of every displayed frame (`c2w`, rows of a 3 x 4 matrix, OpenCV camera axes), the intrinsics, the
keyframes given to the model, the opening view and the `layout` of `points.bin.gz`: positions as uint16 in the cloud's `box`, then
one uint8 block per channel (`photo`, `albedo`, `irradiance`, `normal`, `roughness`, `metallic`), the displayed frame that first
sees each point (`first`) and one bit per keyframe that sees it (`seen`). Points are in Morton order; the world is recentred, y up.

## Where the content comes from

Everything under `assets/` is generated by scripts that live with the model's code (`rgbxt/web/`), not here:

| Script | Makes |
|---|---|
| `web/dl3dv_depth.py` (Depth Pro 2's environment) | a DL3DV clip: frames, COLMAP cameras, Depth Pro 2 depth corrected to COLMAP's scale with the release's multi-view-stereo depth |
| `web/scenes.py` (`web/scenes.json`) | `assets/scenes`: keyframes in ONE model forward, one PointX query per surface point |
| `web/videos.py` | `assets/videos` from the stored maps of the paper's DL3DV comparison |
| `web/surface.py` | `assets/surface` from the dumps of `evals/qual_points.py` |
| `web/consistency.py` | `assets/consistency` from the stored ETH3D maps of the paper's Table 2 and the laser scans |
| `web/eth3d_depth.py`, `web/relight_mesh.py`, `web/relight_eth3d.py`, `web/blender_relight.py` | `assets/relight`. Views of an ETH3D evaluation window with a depth for every pixel (Depth Pro 2 corrected by the laser scan); the views fused into one surface (TSDF); PointX given the THREE photographs that are shown (the three of the window whose frames share most), one query per pixel and per vertex of the surface; a glowing sphere path traced in Blender 4.5 (Cycles) with the predictions as a Principled BSDF, the camera seeing the photograph's own depth map, the fused surface casting shadows and bouncing light; relit = photograph x (0.06 + power x (diffuse light / irradiance + specular radiance / (albedo x irradiance))). Each photograph is shown cropped to the part inside all three frames: a view counts fully up to its frame's edge, so where another frame ends on a wall the pooled prediction steps (irradiance 1-3 %, normal about 1 degree) and a grazing bulb shows it as a line; inside the crop no frame ends. Rays ignore the fused surface within 3 voxels (at least 5 cm) of their start, so contact shadows begin that far out |
| `web/figures.py` | `assets/method`, `assets/apps` from the paper's figures |
| `web/check_benchmarks.py` | checks `js/benchmarks-data.js` against the paper's LaTeX tables, digit for digit |

Geometry of the first panel's scenes: DL3DV's COLMAP cameras and Depth Pro 2 depth, corrected to COLMAP's scale with the release's
multi-view-stereo depth. The geometry only supplies the tracks (where a point projects, and whether it is visible there); the model's
own input geometry is VGGT-Omega's, as trained. (`web/scenes.py` also reads ETH3D SLAM sequences, with the benchmark's depth sensor and
motion-capture poses; they are not shown: those scans are sparse.)

## Visitor counter

The last line of `index.html` is a [GoatCounter](https://www.goatcounter.com) tag: visits and their countries, no cookies, nothing shown on
the page; visits from `localhost` are not counted. The numbers are at https://mlfarinha.goatcounter.com. The anonymous copy never carries
the tag.
